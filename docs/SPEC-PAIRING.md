# CoralVPN — привязка устройства по QR (device pairing)

Версия 1.0 (2026-09-20) · Для серверной команды (endpoints + бот) и клиента.

## Зачем

На ТВ (и вообще на устройстве без удобного ввода) нельзя вставить длинную ссылку подписки.
Решение — «привязка по QR», как логин YouTube/Netflix на телевизоре: устройство показывает QR,
пользователь сканирует его телефоном → бот привязывает устройство к его подписке → устройство
само получает свою `sub_url`. **Копировать ссылку вручную не нужно.**

Работает для любого устройства (ТВ, второй телефон, приставка) — приложение одно и то же.
Платная подписка **без лимита устройств**, поэтому пейринг просто добавляет ещё одно
устройство к той же подписке.

## Общий флоу

```
Устройство (ТВ)                Сервер                         Бот (Telegram)
  |  POST /pair/new  --------->  создаёт сессию (token)
  |  <--- token, deep_link, code, expires_in, poll_interval
  |  показывает QR(deep_link) + короткий код
  |
  |                                             юзер сканирует QR телефоном
  |                                             открывается t.me/Coral_VPN_bot?start=pair_<token>
  |                              <----- бот: /start pair_<token>
  |                              бот находит подписку юзера,
  |                              привязывает устройство, помечает
  |                              сессию ready + кладёт sub_url
  |  GET /pair/status?token (поллинг каждые poll_interval)
  |  <--- {status: ready, sub_url}
  |  сохраняет sub_url → GET sub_url?fmt=singbox → Connect
```

## Endpoints (сервер)

### 1) POST /pair/new
Создаёт сессию привязки.

Запрос (JSON):
```json
{ "device_id": "<uuid>", "kind": "tv|phone|other", "name": "Android TV (опц., для показа в боте)" }
```
Ответ 200 (JSON):
```json
{
  "token": "<непредсказуемый идентификатор сессии, ≥128 бит>",
  "code": "ABCD-1234",              // короткий код-фолбэк для ручного ввода в боте
  "deep_link": "https://t.me/Coral_VPN_bot?start=pair_<token>",
  "expires_in": 300,               // секунды жизни сессии
  "poll_interval": 3               // рекомендуемый интервал опроса статуса, сек
}
```
Ошибки: 429 (rate-limit по IP/device), 400 (плохой device_id).

### 2) GET /pair/status?token=<token>
Опрос статуса привязки (клиент зовёт каждые `poll_interval` сек).

Ответ 200 (JSON):
```json
{ "status": "pending" }
```
```json
{ "status": "ready", "sub_url": "https://sub-ru.ai-boost.tech/sub/<id>", "expire": 1790000000 }
```
```json
{ "status": "expired" }        // сессия истекла или отменена
```
- `sub_url` отдаётся ТОЛЬКО при `ready` и ТОЛЬКО по точному `token`.
- После `ready` статус остаётся `ready` (идемпотентно), пока сессия не подчищена.
- Ошибки: 404 (неизвестный token), 429 (слишком частый опрос).

### 3) Бот: обработка `/start pair_<token>`
- Пользователь открывает `t.me/Coral_VPN_bot?start=pair_<token>` (из QR) — Telegram передаёт боту `pair_<token>`.
- Бот идентифицирует пользователя (его Telegram id) и его АКТИВНУЮ подписку:
  - если подписка есть → привязать устройство к ней, пометить сессию `ready`, положить `sub_url` подписки;
  - если подписки нет → провести штатный сценарий (оформить/продлить или выдать триал), затем завершить привязку;
  - подтвердить пользователю в чате: «✅ Устройство "<name>" привязано».
- Фолбэк по короткому коду: команда/кнопка в боте «Привязать устройство» → ввод `code` из `POST /pair/new` → тот же результат.

## Модель данных (ориентир)

`pairing_sessions`:
| поле | смысл |
|---|---|
| token | PK, случайный, single-use |
| code | короткий код-фолбэк |
| device_id | uuid устройства (для аудита/дедупликации) |
| kind, name | тип/имя устройства для показа в боте |
| status | pending / ready / expired |
| sub_url | заполняется при ready |
| user_id | Telegram id, кто привязал |
| created_at, expires_at | TTL сессии |

## Безопасность

- `token` — криптослучайный, ≥128 бит, непредсказуемый; TTL короткий (например 5 мин); одноразовый на завершение.
- `GET /pair/status` отдаёт `sub_url` только по точному `token` и только при `ready`.
- Rate-limit: `POST /pair/new` и `GET /pair/status` — по IP/device.
- Не логировать `sub_url`/`token` в открытые логи.
- QR/код действителен ограниченное время; после `ready` или истечения — сессия недоступна.

## Контракт с клиентом (что делает приложение)

1. Генерит `device_id` (UUID, уже есть) → `POST /pair/new`.
2. Показывает QR из `deep_link` + короткий код (крупно, для ТВ).
3. Поллит `GET /pair/status?token` каждые `poll_interval`, пока `ready`/`expired`/таймаут.
4. При `ready` сохраняет `sub_url` как обычную подписку → `?fmt=singbox` → Connect.
5. При `expired`/таймауте — кнопка «Обновить код» (новый `POST /pair/new`).

## Открытые параметры (на усмотрение сервера)

- TTL сессии (реко 5 мин), формат `code`, лимиты rate-limit.
- Нужно ли показывать в боте список привязанных устройств и «отвязать» — приятно, но не для MVP.
